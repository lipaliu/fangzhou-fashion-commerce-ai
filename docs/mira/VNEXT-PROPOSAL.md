## 这次到底要做什么

Mira 最左侧新增「爆款模板」。用户在每日热榜里看到的，应当已经是后台拆解、编写好模板提示词且验证可生成的玩法，不是尚待人工拆解的原始视频信息流。

用户路径：选模板 → 看效果视频 → 做同款 → 换衣服 → 换脸 → 换场地 → 可选调整 → 生成一条完整视频。

后台路径：发现并收集候选作品 → 基础去重和相关性筛选 → 管理员/超级管理员看原片并点击「愿意做这个」 → 填写可选拆解指导 → 大模型结合可解析视频与指导进行深度拆解 → 人工检查、补充要求并修订 → 多组素材试生成 → 超级管理员审核上架 → 用户可直接做同款。

收集阶段只保存来源、基础信息、指标快照与线索，不默认对所有候选花费大模型成本做完整拆解。「愿意做」是人工选择；提交拆解时创建异步任务。管理员指导与普通用户的作者灵感是两个独立字段、两个阶段，不能互相混入。

未通过验证的候选只留后台；前台不要求用户再做拆解、编写提示词或确认模板是否能用。

## 本次例子与关键纠正

研究对象：[小椰爆爆🥥提供的抖音作品](https://www.douyin.com/video/7692089168440581489)，以及[同账号对照作品](https://www.douyin.com/video/7684963490964895921)。

原片约 22.75 秒，由约 5.68 秒内容重复四次。第一轮约 0–1.35 秒是悬浮穿搭上身；约 1.35–5.68 秒为造型与花絮快切，包括扶墨镜、伸展、俯拍、补妆、侧后方、手机自拍、杂志等。精确切点为分析近似值。

**这是一个「悬浮搭配」玩法、一条完整视频，不是两个模板，也不是两条输出。** 内部段落区分仅用于理解不同摄影与节奏要求，不让用户分别创建或提交两段任务。

按 Lipa 的最新理解，先建立完整模特终态造型（包括实际穿搭中的墨镜等配饰），再设计约1–2秒的睡衣反差开场。睡衣款式不重要，也不需要用户另传。整套搭配上身后，人物进入模特拍摄状态，pose、补妆和摄影花絮构成核心展示，默认至少保留一个明确片场瞬间。终态造型在后续所有镜头一致。

片场感可以发生在摄影棚，也可以发生在用户指定外景。具体发型、鞋包与墨镜由本次素材决定，不强制复制原片；狗狗、杂志不设为必需。先建立终态是我们的模板规划策略，不能宣称知道原作者用了哪种模型、哪条原始提示词或实际生成顺序。

## 产品页面

### 管理端玩法候选库

- 管理员与超级管理员均可查看候选、看原视频、暂不做、选中和填写拆解要求；建议发布与撤回权限只给超级管理员。
- 候选展示真实来源、采集时间、证据状态、热度核验状态和处理状态。未知作者或热度必须标为待核验。
- 点击「愿意做这个」打开指导框，可先保存，也可发起拆解；模型先看视频，再结合指导输出带时间码的观察、玩法抽象、可替换项、分镜规则、模板提示词与测试方案。
- 模型结果进入待审核，不直接发布。超管可补充提示词发起新版本修订，保留原结果、指导与版本记录。
- 本地演示地址 `/mira-templates/admin.html`。当前手动收录用户案例和3条公开搜索线索；未验证它们是今日爆款，未逐条播放核验新线索，TikTok/Instagram暂为空。
- 本地支持筛选、身份可见性演示、选中、暂不做、保存指导、下载拆解请求；没有模型调用和真实权限系统。正式端必须服务端鉴权，不可用前端下拉框或隐藏按钮代替。

### 爆款模板 / 每日热榜

- 视频卡片，点击预览完整效果，清晰的「做同款」主按钮。
- 平台、玩法、更新时间、收藏、搜索。只有真实可得的数据才显示热度与增长；首采不能展示伪造的 24 小时增长。
- 同玩法多个穿搭变体聚合，避免当作十种不同玩法刷榜。
- 已验证的模板在前台直接可做。原始采集候选、分析失败和模型测试记录放后台。
- 预览当前只用一个真实案例演示；不将其伪装为当日排名第1，也不虚构 TikTok / Instagram 样本。

### 做同款生成页

- 左侧保留小尺寸完整效果，右侧依次：换衣服、换脸、换场地、可选调整。
- 衣服支持任意布局拼图，自动抽取完整穿搭。识别结果可修改；没有额外点击 + 配饰时，直接采用衣服图里有效的搭配。
- 换脸优先「从人像库选择」，复用 Mira 现有人物资产；支持搜索、选择、替换，同时保留上传新人像。生成请求绑定 person_id / 人物素材版本，避免仅传名字。当前预览库为示例与本次添加的人像，不读取线上私人数据。
- +包、+鞋、+配饰、+独立发型按需出现。没启用的内容不污染最终提示词。
- 场景默认沿用模板，支持描述或上传；切换模式后仅生效当前模式，不能将隐藏的旧场景图发给模型。
- 作者灵感为选填，后台语义融合，不原样叠加。视觉质感可选跟随模板、自然、胶片、CCD、富士感、电影感。
- 时长、比例、清晰度按正式服务能力下发；原型中的选项仅为交互示例，不代表 API 已支持。
- 一次生成一条成片。重新生成保留同一个人、穿搭、场景和视觉设定，独立重排合理镜头。无需增加「同拍法重试」，无需三次一起规划。

## 素材与提示词规则

1. 人物身份来自人物图。独立发型存在时只提取该图发型；否则发型来自人物图。
2. 单独上传的指定配饰完整覆盖该类别，不能混用其他参考的同类设计。
3. 衣服拼图按内容识别，不假定左右或上下结构。独立鞋包区域优先于全身图上同类物品；不存在独立区域时采用全身搭配。
4. 场景是空间而非固定背景板。环境光匹配脸、身体、衣服；机位变化自然重建透视。
5. 单镜头内运动连续，切镜是明确剪切；不能把镜头内跳帧误当成切镜。
6. 目标素材、模板规则、作者灵感按属性合并；作者明确更改的场景和动作覆盖模板默认值。关键矛盾需明确指出，不能悄悄丢弃素材。
7. 服装上身过程是明确限定的状态变化；其后所有镜头锁定最终穿搭。
8. 正常速率，按用户目标时长编排；不将原片循环四遍当作时长策略。
9. 续写是另一模式：差值=目标总时长−保留的已有片段时长。不能默认补到8秒，也不拉伸原视频。
10. 只使用经验证的 Doubao Pro 部署，无 Lite、无静默降级；模型失败明确报错。具体 model_id 由正式火山账号核对后配置，不凭模板文档固定未经核实的名称。

## 技术路径建议

拆解一次形成可版本化 recipe；生成时复用，避免每位用户重新分析原片。

图片理解与作者灵感融合 → 冻结本次人物/穿搭/场景设定 → 单次分镜编排 → 服务端校验 → 视频服务适配器 → 输出检查。

如果视频服务支持整条多镜头，则一次提交；如质量测试表明需要分段，内部使用同一设定与衔接约束再组接，前台仍交付一条视频。具体生产路线待实测，不从原片猜测。

成片检查：人物一致性、衣服鞋包正确性、单品落位与副本、发型、场景及受光、镜头内跳变、正确总时长、非循环补时、结构保留。提示词不能保证零错误，需要程序校验与成片检查。

## 每日发现与上架

数据入口适配器统一规范。抖音官方热榜需申请权限；TikTok 趋势入口与 Top Ads 是不同来源，不将广告当自然爆款；Instagram 可用授权范围与供应商待核实。

记录 source_id/platform/url/creator/published_at/observed_at/metrics/metric_scope。增长从多次快照计算，跨平台先分别归一化再聚合。失败任务重试和告警，旧数据显示更新时间，不伪装今日。

rank_score 与 template_readiness 分离：作品很热门但不能可靠生成时，不进入前台可做同款列表。前台素材预览使用获准展示的原作品嵌入或自己的模板测试成片；本次第三方参考视频仅用于本地研究演示。

## 明天程序员建议先做的顺序

1. 核对正式 Mira 仓库和当前上传、任务、生成接口；此仓库是原型，不是已确认的线上源码。
2. 先落一个 floating-outfit 模板及完整做同款流程，后台采用本提案的 Pro 编排器。
3. 用不同人像、整套穿搭与上下/左右拼图、街景等验证可替换能力。
4. 通过后建立模板版本、发布状态与测试记录，前台只读已发布版本。
5. 再接入每日采集、发现、去重与自动模板制作，不以抓到视频代替模板完成。

## 交付范围

本分支提供可点击前端预览、确定性的制作请求预览、提示词草案、模板配方及开发说明。没有接入爬虫、Doubao、图片内容识别、视频生成或支付；不会上传用户素材，不模拟新视频生成成功。收藏和制作请求草稿保存在本浏览器，上传图片不持久保存。

前端素材编号由实际启用项生成，场景模式和配饰移除行为已有可测试逻辑。示例开场固定1.5秒用于演示，正式编排在约1–2秒范围按动作适配，其余时间用于模特展示和片场花絮。
